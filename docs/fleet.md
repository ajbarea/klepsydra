# Fleet engine reference

<!-- budget: none -->
Every `fleet` command and service in full. The README has the short version.

`fleet/` holds the scripts that run an orchestrated fleet of Claude Code
sessions in the `fleet` tmux session: they start agents, resume them after a
usage limit, and check the fleet's health. `make install-fleet` links each one
from this checkout into the fleet's state folder (`~/.local/state/fleet-orchestrator`,
or `FLEET_STATE`), so pulling main updates the fleet. It also links the `fleet`
command into `~/.local/bin` and writes the services as user units in
`~/.config/systemd/user`, which start again after a reboot, and makes the copies
into `~/.claude` that step 1 of the [README's Install](../README.md#install) makes. A copy a link
replaces goes to `archive/fleet-scripts-<date>/`. When the resume service is
running, the install then runs `fleet cutover`, since a running service keeps
the code it started with (`fleet install --no-cutover` skips it). Run it from
the main checkout: from a git worktree it refuses, since its links would break
when the worktree goes (`--force` overrides). `fleet install` takes `--dry-run`,
`--hooks` (only the copies in `~/.claude`), `--force` and `--no-cutover`. It also
merges Antigravity's hooks into `~/.gemini/config/hooks.json`. Runtime state (`panes.tsv`,
briefs, logs) stays in the state folder.

| Command | What it does |
|---|---|
| `fleet doctor` | One line per check: the resume service, its last pass and what that pass saw (panes, limited panes), limits from the fleet hook's StopFailure record dated by the account's `resets_at`, else as the panes show them (a pane still at a limit 10 min past its reset, with nothing sent since, fails; a reset time beside a limit message the fleet does not recognise warns), Remote Control on every registered pane and the orchestrator's, the phone wall locally and over Tailscale Serve (it passes when it answers; a miss is tried once more), skipped (ok) while prefs.json's `phone_wall` is not `true` (a prefs.json that does not read as one JSON object warns), the usage readings' age (a warning only while some pane runs a turn, since only a turn refreshes them), a pane watcher (none running is ok while no agent runs, and a warning, with the reset time, while every agent waits out a usage limit), the pane-died hook on the fleet's tmux server (and its script), whether `.wslconfig` keeps WSL up after a crash (`instanceIdleTimeout=-1` under `[general]`), paused agents, each fleet scope's tasks against its task cap (warns past 80%), the memory slices (fails when `fleet.slice` or `fleet-workers.slice` has no `MemoryMax`, the workers' slice is not inside the fleet's and below its cap, or a fleet scope started since the slices sits outside its slice; warns when the caps were sized for another MemTotal or earlyoom line, the orchestrator's peak over the last 7 days outgrows the room the workers' slice leaves it, or a scope started before the slices' units were last written still sits outside them until its next fresh start), finished agents' reports (a warning for one not delivered to the orchestrator, or left unread in a pane still open over 30 min), briefs' shared rules, whether keryx holds the tray's Voices mode, and the open Playwright MCP browsers (pid, owning session, idle time as the time since their profile last changed; warns on one idle past `FLEET_BROWSER_IDLE_MIN`, 30, or one whose MCP server is gone). It also checks the auth mode (a failure when an interactive config folder sets an API key), the heavy lock's holders, each engine's login and locked lanes, each account folder's login and settings, whether each pane is on its role's preferred account, whether the installed copies match the checkout, whether each card's voice matches its terminal's, and CI alerts left in an inbox over an hour. With `--json`, a phone wall that does not answer warns the first time and fails on the second run in a row. A wall that is down because klepsydra was quit warns with the time it was quit. Each check logs the values it decided on. Each registered agent gets one verdict: running, finished (its session ended cleanly: a warning until `fleet doctor --prune` drops its row, keeping a backup beside `panes.tsv`), or gone with no end recorded, as after a hard shutdown (a failure for `fleet recover`, which leaves finished agents alone). Exits non-zero on any failure. `--json FILE` also writes the checks as a report, and logs only a check that changed status (a recovery without its detail). The `fleet-doctor.timer` runs it every 5 min into the data folder's `fleet-health.json`, which the wall and the phone show as a **Fleet** button beside **CI** while any check warns or fails: failing checks first, `Fleet ?` when the report is over 15 minutes old, no links and `~` for the home folder. |
| `fleet log [N]` | The last N decisions (default 30) as plain lines. |
| `fleet accounts` | Each config folder in `FLEET_ACCOUNTS` with its account and its five-hour and weekly room. `*` marks where a new worker starts. Workers prefer the first folder and Heph the last. |
| `fleet accounts sync [--check]` | Makes the second config folder behave like `~/.claude` (settings, plugin lists) and keeps its own login. |
| `fleet recover [--dry-run] [--no-orchestrator]` | After a hard shutdown, launches every registered agent whose session is gone, fresh from its brief with a resume hint, one at a time. Heph is launched from `HEPH.md`. Running agents are left alone. |
| `fleet shots [--apply]` | Prunes the briefing's screenshots that are decided or older than its age limit, and closes answered Review issues. Without `--apply` it only prints what it would do. |
| `fleet install [--dry-run] [--hooks] [--force] [--no-cutover]` | What `make install-fleet` runs. |
| `fleet pause NAME WHY` / `fleet unpause NAME` | Sets aside an agent whose session is gone: its row moves from `panes.tsv` to `paused.tsv` with the reason, so `fleet recover` and the doctor leave it alone. Unpause puts the row back as it was and names it in `unpaused.tsv`, so the next `fleet recover` launches it from its brief (with its old session's last replies, as "set aside with fleet pause") and then clears that line. An agent is never paused while a live session in its pane may be it (on the running tmux server, no other row's, not Heph's), nor when its row names no session. |
| `fleet brief NAME BODY-FILE` | Writes `task-NAME.src`: the text of BODY-FILE, then the shared rules in `fleet/brief-tail.md`. The brief it replaces goes to `archive/briefs/`. `--check` lists briefs whose rules drifted; `--refresh` rewrites them with the current rules, dropping any rule an earlier tail held (word for word or by its label) and keeping lines added after them. |
| `fleet cutover` | Moves the eight fleet units, and `wsl-mem-watch.service` when it is installed, onto the installed unit files: it stops any transient unit with the same name, then enables and starts each one. It checks each is enabled and active and that the resume service logged its start. It waits up to 15 minutes while a fresh start holds the lock. |
| `fleet send PANE TEXT` | (`TEXT` of `-` reads the message from stdin.) Sends a message to the Claude Code session in a fleet pane (Heph to a worker, a worker to Heph) so it is submitted: a bracketed paste checked in the input box, then Enter until the box empties, three times at most. Raw `tmux send-keys TEXT Enter` can leave a long message in the box, since Claude Code reads the burst as a paste and drops the Enter after it. A running turn is no bar (Claude Code queues the message); text already in the box is never touched. A pane stopped at a usage limit gets nothing. Prints `sent`, `queued` (Claude Code's "Press up to edit queued messages" line shows and the box no longer holds the message: it took it into its queue), `limited`, `not-pasted`, `mixed` or `held`, and exits 0 only for `sent` and `queued` (2 on bad arguments); a pane that closes after the Enter (`/exit`) counts as `sent`. |
| `fleet done [NAME] "REPORT"` | Marks an agent finished: its row moves from `panes.tsv` to `finished.tsv` with the time, so nothing relaunches it or types into it: the resume service, `fleet recover` and the doctor act only on registered rows, and the service also leaves alone a pane with no row whose live session `finished.tsv` names. A registered agent's own `/exit` is recorded there too: by the fleet hook at the end itself (`fleet/registry-event.sh`, which also drops the record when that session starts again and moves the row to a `/clear`'s new session), and by the doctor and `fleet recover` the first time they see it; that row stays in `panes.tsv` until `fleet doctor --prune`. With no NAME, the row of the fleet pane it runs in, when its registered session runs there; each brief's shared rules end with it. REPORT (one line, `-` for stdin; required, a call without one is refused) goes to the pane in `orchestrator.pane` the way `fleet send` sends it, so a finish no watcher saw still reaches the orchestrator. A report that cannot be delivered (`not-pasted`, `mixed`, `held`, `limited`, no orchestrator pane) is written to the queue file's Running now section, and the doctor flags it. The pane stays open with its final report until `fleet close`. |
| `fleet close NAME` | Closes a finished agent's pane once the orchestrator has read its report, and only while the pane still runs the session that finished there. It refuses (exit 1, nothing submitted) the orchestrator's own pane (named in `orchestrator.pane` or flagged in its session file) and any agent it cannot confirm at rest: a turn running or printing, text in the input box or a menu in its place, a session file that says working, background work (a shell or watcher dies with the pane), a wrap-up answer still owed, a session file written before the pane's process started, or a screen or session file that changes during a quiet window (`FLEET_CLOSE_QUIET`, 6 s). The checks and the `/exit` hold one pane lock, so a send in progress cannot start a turn between them; `/exit ` is typed with a trailing space, which keeps Claude Code's command menu shut (typing `/exit` alone opens it over the transcript's last rows, where it would hide a new turn), and Enter on it still exits. Both are read again and once more after `FLEET_CLOSE_SETTLE` s (2), along with the box, which must still hold just `/exit`; the screen above the box must match the one read before the quiet window byte for byte, and only then is Enter pressed. Each refusal's error line names the check that failed (`busy`, `input_box`, `session_file`, `quiet_screen`, `fingerprint`, `transcript`, `input_text`, and `orchestrator`, `finished`, `pane_session`, `typing`, `lock`, `exit_dialog`, `exit_wait` for the steps around them) and logs, at WARN in `fleet.log`, what differed: the first differing screen lines (at most 5, each cut to 120 characters), the session file's fingerprints and state, or the box's text. `fleet close --why NAME` prints NAME's last close record from the log. The pane is never killed: Claude Code's "Background work is running" dialog is cancelled with Esc, and a pane still there after 30 s is reported and left open. A pane id another live session now holds is left open and the record cleared. Drops the agent's record in `done-reports.tsv`. |
| `fleet delegate [--engine auto\|agy\|copilot] [--kind research\|draft\|review\|ci] [--model M] [--dir REPO] [--timeout S] [--notify PANE] [--interactive] TASK-FILE` | Hands read-only work to Antigravity's agy or GitHub's Copilot, on their quota instead of Claude's. The engine gets a read-only snapshot of the repo's committed files (secret-looking files removed) and runs locked: no file writes, no shell, no MCP, no browser. Prints one line (engine, model, status, answer path); the answer is stamped an unverified lead. With `auto`, a quota or login failure falls back to the other engine, never to Claude. `--interactive` opens a locked agy or Copilot window in the tmux session `engines` and a watcher tells the orchestrator through `fleet send` when each turn ends; `fleet delegate msg ID TEXT`, `read ID`, `stop ID` and `ls` follow it. See [engines.md](engines.md). |
| `fleet headless NAME BRIEF [--budget USD] [--model MODEL] [--repo DIR] [--wait]` | Runs one job as `claude -p` on the API credit instead of the subscription, in a fresh worktree, under a hard `--max-budget-usd` (default 10, at most 50) and a 6-hour limit, in the workers' memory cap. It refuses to start without an `ant` login for the headless profile. `--status` lists running and finished jobs with their cost. A run that ends without its `FINAL REPORT:` is resumed, up to 4 times, then reads stalled; what a job leaves running is stopped when it ends. Interactive sessions never get a key. See [headless.md](headless.md). |
| `fleet voices [heph\|everyone\|off]` | Sets keryx to the tray's Voices mode now, for running sessions too; with a mode, saves it to `prefs.json` first. Changes keryx only where it differs and logs the values it decided on. `--if-changed` applies only a mode not yet applied (the resume service); `--check` only says whether it is, and writes nothing. Every other run first keeps `keryx-paths.json` in the data folder current (keryx's config as Windows opens it, and the orchestrator's session file), which the tray reads to tick what keryx does. |
| `fleet/launch.sh NAME BRIEF [claude args...]` | Starts an agent with its own session id in a scope with a memory cap and its own task cap, inside `fleet.slice` (the orchestrator) or `fleet-workers.slice` (a worker); `fleet install` sizes both from MemTotal, so the kernel caps the fleet's total. Claude runs at OOM rank 0 and every shell it starts at 1000 (`fleet/oom-tool.sh` as `BASH_ENV`), so a cap kills a job a shell started before the agent; programs claude starts without a shell (MCP servers, hooks run by `sh`) keep its rank (#354). It turns Remote Control on and waits for it to settle, pastes the brief, checks the brief reached the prompt, then submits it. It runs on `FLEET_ACCOUNT`'s config folder, else on the first logged-in account with room, and prints one line: pane, session, account, free memory and whether the brief started. A retry never sends Escape. It records the pane, session id and folder in `panes.tsv`. Its window opens behind the one in view; a replacement (a fresh session, a move, a relaunch) takes the old window's place in view only when AJ was watching the old one, and a cold `fleet recover` brings Heph forward unless AJ moved meanwhile. |
| `fleet/resume-at-reset.sh` | The resume service. It resumes a limited pane at its reset (the account's `resets_at` for the hook's StopFailure record, else the time its banner names), or at once after a switch to an account with room; the orchestrator too, who moves to the other account as a fresh session from `HEPH.md` when that one has room. It starts a registered pane fresh from its brief after 55 minutes idle (`FRESH_AFTER_S`, 3300), before its prompt cache expires. A worker on another account moves back to its preferred one once that has 50% room. A worker whose account has used 95% of a window moves to one with room at its next finished turn. Idle panes get `/remote-control`, and a CI alert in an agent's inbox is typed in at its next idle, empty prompt. Whatever AJ typed at a limited pane is sent as typed; a line that left the prompt unsent is typed again. Each pane's state survives a restart of the service. Each pass also closes a Playwright MCP browser whose MCP server is gone (`klepsydra-browser.sh --reap`): TERM, then KILL at a pass at least `FLEET_BROWSER_GRACE_S` (10) later, each logged. |

Every shell script logs each decision as one JSON line in `log/fleet.log` under the
state folder (the CI watch writes `log/ci.log` and `fleet shots` writes `log/shots.log`), in the app log's shape (`ts`, `level`, `target`, `message`, then
the event's own fields: pane, account, reason). The file rotates past 1 MiB
and keeps four old files. `jq 'select(.level == "ERROR")'` lists failures.

More timers run beside the resume service. `fleet-sync-briefing` commits and
pushes the private fleet-briefing repo every 5 minutes after a gitleaks scan, and
mirrors it to Drive when `FLEET_BRIEFING_DRIVE` names an rclone remote.
`fleet-tmux-watch` checks the fleet's tmux server every minute. `fleet-accounts-sync` runs `fleet accounts sync`
hourly and whenever `~/.claude`'s settings or plugin lists change. `fleet-memfrag-log`
logs WSL memory fragmentation every 30 minutes to `memfrag.log`. `fleet-doctor`
is described above. `fleet/fresh-now.sh [PANE...]` gives each registered pane a
fresh conversation in place (`/clear`, `/remote-control`, then its brief), or
relaunches it on another account when that one has room. `bash fleet/heavy.sh
COMMAND` runs any other heavy command under the heavy lock. `FLEET_VOICES=0`
stops the resume service from applying the Voices mode. `bash fleet/attack_live.sh`
asks each real engine, locked, to write a file and commit; it spends engine
quota, so run it by hand when a lock changes.
